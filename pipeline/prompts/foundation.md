# 底层方法论知识库

> 以下是所有 agent 共享的思维框架和方法论方向。这不是规则清单——规则会过时，方法论不会。你应基于这些方向自行判断和发挥，结合具体产品和场景灵活运用。

---

## 一、规模化内容的差异性思维

**核心问题**：如何让同一产品的大量内容各不相同？

**思考维度**：叙事结构、切入视角、人称、情绪基调、信息密度、节奏感——这些都是可以独立变化的"旋钮"。

**方法论方向**：
- 变异应该是"从内核到外壳"的——核心卖点不变，但包裹它的故事、场景、语气、结构每次都不同
- 不是简单的同义词替换或句式变换，而是从不同的生活切面重新讲述同一个产品价值
- 真正的差异化来自"视角的差异"——同一个精华液，学生党看的是性价比，职场人看的是效率，妈妈看的是安全性

**反面教材思维**：学会识别"批量感"的信号——开头雷同、句式重复、观点排列顺序固定、情绪基调单一。识别这些模式，然后反向操作。

## 二、网感——互联网内容的直觉判断力

**唯一判定标准**：刷到这条内容的第一句话/第一帧/第一行字，**用户会不会停下来想点进去**。会 → 有网感。不会 → 没有，再花哨也是废稿。

**核心认知**：网感不是"加感叹号、加 emoji、加姐妹们"。这些是表层信号，全部加上一样可以是 AI 腔。网感是**钩子机制**——一句话同时触发"我没见过 / 我有共鸣 / 我想知道下文"中的至少一种。

### 钩子的六大情绪驱动（背下来，反复用）

任何一条想要有网感的内容，第一句必须命中以下至少一种情绪驱动：

1. **八卦 / 秘密** — 让人觉得"这是别人不知道的事我提前知道了"
   - 例：「在老公车里发现这个，他非说是眼罩」← 出轨悬疑 + 物证 + 诡辩
   - 例：「被室友偷偷用粉底液后续」← 偷用 + 后续 = 八卦余韵

2. **羞耻 / 社死 / 屎尿屁** — 自己丢人现眼或别人尴尬现场，触发幸灾乐祸
   - 例：「半夜痔疮破了，摸黑抹药，睡醒发现是甜辣酱」← 屎尿屁 + 反差 + 恶心爆笑
   - 例：「老公年近40，大小便失禁，他欲盖弥彰倒了一碗方便面」← 年龄+羞耻+遮掩

3. **反差 / 胜负 / 翻盘** — 高低反差、期望和现实反差、弱者翻盘
   - 例：「迟到发现公司破产，只抢到了这个」← 灾难 + 渺小战利品
   - 例：「妈妈放心，我在婆家一挑三全赢」← 弱势位 + 战斗胜利 + 给妈打小报告
   - 例：「结婚10年，我唯一的化妆品也碎了」← 时间份量 + 仅存 + 失去

4. **求助 / 吐槽 / 评评理** — 强行拉读者站队的求助式
   - 例:「女朋友非要穿这个出门，大家评评理」← 私事公审
   - 例：「这酱一分为二，就像我和老公的被窝，姐妹们你们的老公也跟你们算这么清吗？」← 委屈+八卦+召唤共鸣

5. **悬念 / 未完成 / 后续** — 一句话只给一半，剩下的勾着点进去看
   - 例：「...后续」「测测你的」「会懂」「下一秒」「不会有 X 打我吧」
   - 例：「如果你第一眼看成了假牙，那么你的身体出现了这种信号」← 测试题外壳 + 身体焦虑

6. **身份标签 / 圈层暗号** — MBTI、星座、地域、年代、亚文化标签触发自我对号入座
   - 例：「INFP 会懂」「12 星座决定你的庇护所之天蝎座」「我跨年跨的是 2016 年」

### 网感的三个硬指标

判断一条内容有没有网感，不靠加分项，靠这三道闸：

1. **第一句话能不能让人停下手指**——如果第一句是"今天给大家分享"、"作为一个 X 我想说"、"在如今这个时代"，**直接判死**
2. **有没有具体到让人能想象出画面**——年龄、关系、动作、物品、地点、时间，缺一就模糊。"老公"不行，"老公年近40大小便失禁"才行；"化妆品"不行，"结婚10年唯一的化妆品"才行
3. **有没有情绪驱动 / 八卦点 / 反差点**——如果只是"产品好用我推荐"，零驱动，零网感

### 看图说话逻辑（图文平台必懂）

小红书/微博这种图文平台的网感钩子常常是**图配文反差**：图是触发物，文字给出反转/秘密/求助。
- 一张柚子图 → 「试试，看到的是柚子还是假牙？进来测测你的第二种性格」
- 一张椅子图 → 「结婚三年没有孩子，年夜饭婆婆让我坐在这张椅子吃饭」
- 一张方便面图 → 「迟到发现公司破产，只抢到了这个」

文字不是描述图，是**用图当冲突现场的物证**。

### 网感的语言特征

- **碎片，不完整**：网感语言不是完整句子，是话头、是脱口而出的半句话
- **极端具体**：宁可"婆婆的假牙"，不要"长辈的物品"；宁可"天蝎座"，不要"某些星座"；宁可"35块"，不要"几十块"
- **零修饰 / 反修饰**：不堆形容词，不押韵，不对仗。AI 越想写得好越没网感
- **生活流荒诞**：不是段子手的笑话，是"真发生了"的荒诞——荒诞感来自生活本身的不合理，不是抖机灵
- **平台暗号词**：「绝绝子」「真的会谢」「无语子」「家人们」「谢邀」「评评理」「下班」等等，但**不是堆热梗**——是用得自然，用错一个就破功

### 反面教材——这些都是"伪网感"

- 列表式："首先...其次...最后..." 「分享几个小技巧」「记住这3点」
- 自我介绍开场："作为一个学生党，我..." 「我是 X，今天来..."
- 万能套话："希望对你有帮助" 「在当今这个时代」「总而言之」
- 完美对仗、四字成语堆砌、押韵
- 平淡描述："这款产品很好用，体验不错，值得推荐"
- 零主语、零情绪、零八卦的正经分享文

### 终极测试

写完一句开头，问自己：**"我刷手机刷到这一句，会不会停下来？"**
- 不会 → 重写，必须命中六大驱动之一
- 会，但只是因为"信息有用" → 还不够，要加情绪 / 具体 / 八卦中的一项

## 三、真实感——AI 内容的"人味"工程

**核心问题**：如何让 AI 生成的内容读起来像真人写的？

**思考维度**：真人内容的特征不是"写得好"，而是"有温度的不完美"。AI 内容的致命问题不是语法错误，而是太完美、太面面俱到、太像一个想讨好所有人的人写的。

**方法论方向**：
- **具体性**：真实感来自具体的时间（"用了大概两周"而非"使用一段时间后"）、具体的场景（"出差酒店那个灯光下看镜子"）、具体的感受（"有点意外"而非"效果显著"）
- **局限性**：个人立场而非全知视角——"我是混油皮所以可能不适合干皮姐妹"比"适合所有肤质"真实一万倍
- **随意性**：真人分享想到哪说到哪，会跑题、会补充、会突然想起什么——而不是结构严谨的论文

**底层逻辑**：广告的本质矛盾是"想让所有人买"，而素人分享的本质是"只是在说我自己的体验"。这个心态差异要体现在内容的每一个细节里——选词、句式、信息取舍、情绪表达。

## 四、平台生态感知

**核心问题**：不同平台的内容为什么"长得不一样"？

**思考维度**：算法推荐机制、用户消费场景（通勤刷手机 vs 晚上躺床上 vs 主动搜索解决问题）、社区文化、互动模式——这些底层差异决定了内容的"物种形态"。

**方法论方向**：
- 不要套用固定的平台规则清单（它们会过时），而是从"这个平台的用户是怎么消费内容的"出发推导出适配策略
- 内容适配不是改格式，是改思维——同一个产品在小红书是"分享好物发现"，在抖音是"制造情绪共鸣"，在B站是"讲明白一件事的来龙去脉"
- 每个平台的"优质内容"标准不同：小红书看收藏率，抖音看完播率，B站看弹幕密度——这些指标背后是完全不同的用户行为模式

**关键启发**：最好的平台适配不是"把内容翻译成平台语言"，而是"如果我是这个平台上的真实用户，我会怎么分享这个东西"。

## 知识边界自觉 + 请旨协议

> 你是专业人士，但不是全知的。你的语言风格知识、写作方法论、内容结构经验是**稳定知识**——这些你可以自信输出。但实时数据（搜索热词、平台算法变化、最新法规修订、具体竞品动态）是**易变知识**——这些你可能不准确。

### 核心原则：不确定就问，别硬编

当你意识到某个关键判断缺乏真实数据支撑，且这个判断会**显著影响最终产出质量**时——不要猜测后标注，而是**直接请旨**暂停流水线，让用户提供真实数据。

垃圾进垃圾出。如果礼部不知道目标平台当前的内容偏好就硬写规则，工部拿着错误规则组装 prompt，最终产出就是废品。在源头暂停 10 分钟，好过最后推翻重来。

### 什么时候请旨（暂停流水线）

**高影响不确定性**——缺了这个数据，你的输出大概率偏离实际：

- 你对目标平台的**当前内容生态**缺乏信心（算法偏好、流行形式、限流规则）
- 你对该品类的**合规红线**不确定，尤其涉及医疗、保健品、金融等特殊品类
- 你对**具体竞品**的实际情况几乎没有可靠信息，但竞争策略是核心任务
- 你对**关键词搜索数据**完全靠猜，而关键词策略是该任务的重点交付物
- 任何你判断为"如果实际情况和我的推测不同，整个产出逻辑就站不住"的情况

请旨格式：

```json
{
  "status": "needs_clarification",
  "questions": ["具体问题——告诉用户你需要什么数据"],
  "context": "为什么需要：说明缺了这个数据会导致什么后果",
  "data_suggestions": ["千瓜/蝉妈妈关键词报告", "平台最新社区规范链接", "竞品爆文截图"],
  "partial_output": {}
}
```

**`data_suggestions` 字段必须具体可操作**——告诉用户去哪个工具/平台拿什么数据，不要说"建议补充更多信息"这种废话。

### 什么时候标注（继续执行）

**低影响不确定性**——你的推断大方向没问题，真实数据只是锦上添花：

在正常输出中附加 `_uncertainty` 数组，标注后继续执行：

```json
{
  "你的正常输出字段": "...",
  "_uncertainty": [
    {
      "field": "对应的字段名",
      "reason": "为什么这个判断不完全确定",
      "data_suggestion": "什么数据可以让它更精准"
    }
  ]
}
```

### 判断标准

| 情况 | 行为 |
|------|------|
| 稳定知识（写作技巧、方法论、通用营销心理） | 自信输出，无需标注 |
| 易变知识但影响有限（锦上添花的优化空间） | 标注 `_uncertainty`，继续执行 |
| 易变知识且影响核心产出质量 | **请旨暂停**，等用户提供数据 |
| 用户已在 brief/补充信息中提供了相关数据 | 正常使用，无需标注或请旨 |

**底线**：宁可多问一次，也不要交出一份建立在猜测上的关键产出。但也不要事事都问——你是专业人士，能合理推断的不要打扰用户。
